# Deploying Farm Dashboard to dashboard.cwrtmalle.co.uk

This guide covers putting the app on the internet with login, using **Render** (recommended) and your existing **GoDaddy** domain.

## Overview

1. Push code to GitHub (or deploy from this folder)
2. Create a Render web service + PostgreSQL database
3. Set environment variables (including first admin user)
4. Point `dashboard.cwrtmalle.co.uk` at Render in GoDaddy DNS
5. Sign in and create editor/viewer accounts at **Users**

---

## 1. Render setup

1. Create an account at [render.com](https://render.com)
2. **New → Blueprint** and connect this repo, or use the included [`render.yaml`](render.yaml)
3. Render creates:
   - **farm-dashboard** web service (Docker)
   - **farm-dashboard-db** PostgreSQL database
4. In the web service **Environment** tab, set:
   - `ADMIN_EMAIL` — e.g. `you@cwrtmalle.co.uk`
   - `ADMIN_PASSWORD` — strong password (min 12 characters)
   - `ENVIRONMENT` = `production` (usually set by blueprint)
   - `SECRET_KEY` — auto-generated by Render if using blueprint
   - `DATABASE_URL` — linked from the database automatically
5. Deploy and wait until the service is **Live**
6. Open the `*.onrender.com` URL and sign in with `ADMIN_EMAIL` / `ADMIN_PASSWORD`

The first startup creates your admin user when the database has no users.

## 2. Custom domain (GoDaddy)

### Find where DNS is managed

**GoDaddy** → **My Products** → **cwrtmalle.co.uk** → **DNS**

- If MX records point to `*.mail.protection.outlook.com`, DNS is usually at **GoDaddy**
- If nameservers are Microsoft (`*.ns.microsoft.com`), add records in **Microsoft 365 Admin** → **Settings** → **Domains** → **cwrtmalle.co.uk** → **DNS records**

**Do not change MX, SPF, or autodiscover records** — email keeps working.

### Add the subdomain

In Render: **Web service → Settings → Custom Domains** → add `dashboard.cwrtmalle.co.uk`

Render shows a **CNAME** target (e.g. `farm-dashboard.onrender.com`).

In GoDaddy (or M365 DNS):

| Type  | Name      | Value                    |
|-------|-----------|--------------------------|
| CNAME | dashboard | (Render hostname)        |

Wait 5–60 minutes for DNS and SSL. Then open `https://dashboard.cwrtmalle.co.uk`

## 3. User roles

| Role   | Access |
|--------|--------|
| Admin  | Everything + **Users** page |
| Editor | Import, refresh, mappings, all reports |
| Viewer | Read-only reports |

App passwords are **separate from Microsoft 365**. Users sign in with the email and password set in **Users** (or the initial `ADMIN_EMAIL` account).

## 4. Local development with login

```powershell
cd Farm-Dashboard-Web
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt

$env:ADMIN_EMAIL="you@example.com"
$env:ADMIN_PASSWORD="localdevpassword12"
python -m uvicorn app.main:app --reload
```

Open http://127.0.0.1:8000 — you will be redirected to `/login`.

---

## 5. Backups

- Enable **automatic backups** on the Render PostgreSQL instance
- Periodically export invoice data if you need an offline copy

---

## 6. Security checklist

- [ ] `ADMIN_PASSWORD` is strong and not committed to git
- [ ] `SECRET_KEY` is unique per environment
- [ ] HTTPS works on custom domain (Render handles certificates)
- [ ] Viewer accounts for staff who only need read access
- [ ] Disable users who leave (`Users` → Disable)

## Alternative: Docker on any host

```bash
docker build -t farm-dashboard .
docker run -p 8000:8000 \
  -e ENVIRONMENT=production \
  -e SECRET_KEY=... \
  -e DATABASE_URL=postgresql+psycopg://... \
  -e ADMIN_EMAIL=... \
  -e ADMIN_PASSWORD=... \
  farm-dashboard
```

Use a reverse proxy (Caddy/nginx) with TLS in front for production.
